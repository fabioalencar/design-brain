## Decision

Harvesters and agents write only to inbox/ (status: candidate), inventory/, and patterns/. Only Fabio moves a candidate to decisions/ via bun run promote. skills/ and exports/ are regenerated by bun run compile from decisions/ and patterns/ and are never hand-edited; a --preview build may include candidates but stamps every file and line as unreviewed.

## Why

The failure this project exists to fix is an AI confidently applying directions Fabio never gave. An auto-accepted rule is that failure with a memory. Keeping the ledger as source of truth and the skills as derived output also means a wrong rule is fixed once, in one file, and every skill that cites it is regenerated.

## Alternatives rejected

Hand-written skills maintained directly — drift between what was decided and what the agent reads, no evidence trail. Agent-promoted candidates above a confidence threshold — confidence is the agent's own estimate; it is exactly the thing being distrusted.

## Consequences

Fabio has a review chore (118 candidates in the first pass). Until it happens the installed skills are a preview and say so. The promote script owns id allocation for DB-### the way forge ddr apply owns DDR-###.
